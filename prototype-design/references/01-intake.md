## Step 0 开局摸底（动手前强制）

> 典型返工根因往往是「开局就该知道却靠返工才发现」：组件类型误判、多套设计器/CSS 混淆、画布宽度/scale 误判、样式表没拉全、脱离 runtime 后布局塌陷、已有规范没复用。
>
> **铁律**：任何产线、任何页面，**写第一行高保真 HTML 之前**必须先在真实环境做一次侦察，产出 `demands/<ID>/<ID>-recon.md`（或 `.json`），清单齐全才许开画。

### 建议动作

1. 在真实页面/弹窗/面板上采集：产品线、目标组件类名与实测宽高、viewport 与 root scale、runtime 类型（static / spa / 小程序等）、样式表完整加载序、页面形态（独立页 / 嵌入模块 / 弹窗 / 侧栏）。
2. 检索你们私有库中的可复用壳/组件片段与反模式。
3. 若功能有前端源码：整理「要画哪些页 / 穷尽哪些态 / 真实文案 / 弹窗子件」真相卡，并写入 recon 的覆盖清单。

### 开局必答清单

| 字段 | 必答内容 | 不答的常见后果 |
|---|---|---|
| productLine | 明确产线/端（管理后台 / 设计器 / 学员端…） | 两套 CSS 混淆 |
| styleSheets | 真实加载序的完整 CSS 清单（禁止猜路径） | 组件裸样式 |
| viewportWidth + rootScale | 设计宽度 + 外层 scale（iframe 会骗人） | 宽度误判 |
| runtimeKind | static / spa / uni-app / 其它 | overflow/scoped 塌陷 |
| targetComponent + Rect | 顶层类名 + 实测宽高 | 组件类型误判 |
| pageForm | 独立页 / 模块嵌入 / 弹窗 / 侧栏 / 子视图 | 做成错误宿主 |
| reusableSnippets | 已沉淀片段 + 硬性约束摘录 | 规范没抄 |
| truthCards | 源码真相覆盖清单（有源码必产；无源码显式降级） | 漏态 / 臆造文案 |

## 前置条件（任一不过禁止进绘制）

| 检查项 | 通过判据 |
|---|---|
| Step 0 recon 齐全 | 上表字段有证据 |
| 目标产线已知 | 来自 recon.productLine |
| 真实样式可复现 | CSS/sprite/字体按团队约定已就绪 |
| 浏览器可测 | 本地预览或 DevTools/MCP 可用 |
| 反模式已检索 | 对应产线节已读，正文列出 |

## 起步检索（强制写进正文）

原型轮次开始前必须检索私有 snippet / 反模式库，并在响应正文明示：

```text
本轮可复用：
  - <壳或组件路径>（约束：…）

本轮需规避：
  - <反模式编号或简述>
```

省略此步 = 违规。
