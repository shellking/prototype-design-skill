## Stage 3：高保真装配原则

> **定位**：替换「徒手写三千行 HTML」的脆弱做法。阶段停点与人工闸不变。

推荐路线（团队可实现为编译器，或严格人工装配）：

1. **声明式优先**：用简短 spec / 清单声明帧、壳、组件态、说明编号；由工具或固定脚手架生成 HTML。
2. **缺件先补库**：真实页采集 → 固化进私有 registry → 再声明复用。一次性探索稿不算正式交付豁免。
3. **禁手改编译产物**：打回改声明字段后重生成；禁止在生成 HTML 上「手术」后当终稿。
4. **血缘可追溯**：交付物应能指回源声明与所用壳/组件版本；手改生成物应视为不合格。

### 补库 SOP（缺件时执行一次）

1. **来源**：真实页 live capture（首选），或已过用户评审的帧提取。切片须标签配平。
2. **CSS**：`requires_css` 必须抄源页实际加载清单；抄错批次会导致部件白渲染。
3. **锚点**：组件内用 **authored 中性 wrapper** + `data-anchor`；虚线不挂真实组件类名。
4. **states**：每态一个片段；组件 CSS 写入各 state（装配时按组件名去重）。
5. **params**：必填无默认、可选有默认；值一律纯文本转义，禁止借参数走私 HTML。
6. **入库登记**：名称、kind（component|shell）、profiles、states、default、params、anchors。
7. **冒烟**：最小声明装配一次，容器 flex / 说明栏位置正确再登记 INDEX。

### 离线渲染注意

`file://` 下外链大 CSS 可能延迟加载。断言/截图前须等样式表就绪。「巨图标默认 300×150 / header 失高 / 只剩 inline 样式」常是 CSS 未加载完的假象，先排除加载态再诊断规则。

### 低配模型友好：万能画布（可选）

维护「standalone 原型帧画布」：一次性烘入壳 + 组件 CSS 子集 + **容器/标注层 CSS** + 三槽（帧标题 / 产品内容 / 说明）。复制画布 → 只填三槽 → 贴库内片段，减少装配错误。多片段同画布时注意 CSS 选择器隔离，避免后加载规则覆盖前者。

### 容器层硬约束（与设计系统一致）

- `.proto-layout` 必须为横向 `display:flex`（禁止改成 column 把说明栏挤到下方）
- 一帧内可见弹窗遮罩 ≤ 1（每状态独立成帧）
- 标注层 CSS 来自容器设计系统，禁止按需求改色值/栏宽
