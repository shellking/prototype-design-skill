## 自验原则

高保真 done 前建议完成：

1. **当前文件身份**：对当前 HTML 取内容哈希；后续 runtime/截图证据必须绑定该哈希，禁止复用旧文件证据。
2. **结构 + 交互**：关键选择器存在；弹窗/抽屉可见性、居中、footer、层级、滚动条有断言（若页面含遮罩层）。
3. **真实-vs-本地**（声称对齐真实时强制）：
   - 镜像真实页完整样式加载序
   - 采集真实基准：截图 + 关键元素 `getBoundingClientRect` + computed style
   - 本地同元素同测
   - 数字（宽/高/字号）+ **overflow 检查** + 并排截图肉眼核
4. **不达标**不得用「完成 / 已对齐 / 可审阅」；缺真实基准只能标「方向草稿」。

**硬约束**：结构通过 ≠ 视觉正确。证据过期、哈希不匹配、空工作集、缺状态，均视为无效。

### Diff 闭环

真实对齐类原型先声明 ROI 与必过断言。任一失败须落入缺陷单；存在未关闭的阻断项时不得进用户审阅。修复后重采同 ROI、更新关闭证据。

## Stage 3.5 交卷前自评（pre-emit）

调独立评审（裁判）**之前**，画原型的主代理（运动员）先做机械自检并修好看得见的低级漏。

- **不是**运动员给自己打最终分。出分 / 判过仍是裁判专属。
- 建议 5 项：①逐态全画 ②不命中反模式 ③文案净化（产品 UI 无需求语/「本期新增」徽标）④无重叠/异常溢出 ⑤与澄清/结构稿一致。
- 每项填 `pass|fixed|na|fail` + 证据；裸勾选无证据 = 不合格。
- 若有真相卡覆盖清单：每项 `covered`（写帧号）或 `waived`（写理由）；全 waived / 零命中冒充通过 = 不合格。

## Stage 4 独立评审

- 调用独立 reviewer（人或子代理），传入原型路径与需求 ID。
- **运动员/裁判分离**：画的人不能兼最终评分。
- 标准答案：澄清 + 结构稿 + 容器设计系统（没写的不扣分）。
- 建议维度：设计系统合规、一致性、交互闭环、文案、层次洁净、规范遵守、保真度、规格吻合、范围吻合。阻断维 FAIL → 打回修后再评。

## 五条铁律

1. **复用**：有沉淀的真实壳就复用，禁手画近似壳；禁 `display:none` 藏标准壳充数。
2. **保真**：对齐必须有像素/截图证据，不能只比单个数值。
3. **裁判先于用户**：递交用户审阅前应有 fresh 独立评审通过；不要把用户当第一个检查员。
4. **捕获取整页**：捕获取 `body` 全兄弟链（含 footer/header），勿只取目标组件 `outerHTML` 导致漏件。
5. **自核**：每版渲染后自己能看见的错直接改（重叠/错位/缺件），不推给用户确认「你看要不要改」。
