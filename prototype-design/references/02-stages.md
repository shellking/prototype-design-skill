## 阶段流水

每个 **■** 是 end-turn 人工停止点。

```
Stage 0  开局摸底 recon
         闸：recon 清单齐全（有源码时含真相卡）——否则禁止任何后续
   ↓
Stage 1  结构确认稿 + 低保真灰盒线框
         闸：结构完整；新形态须发散 ≥2 个结构方向 + AI 推荐，交用户锁定
   ↓ ■停：交用户审线框+结构；用户确认后才签「结构已确认」（禁 AI 自签）
Stage 2  澄清文档（字段有来源、范围对账、页面流程图）
         闸：澄清必填段齐全
   ↓ ■停：交用户审澄清；用户确认才准开画
Stage 3a 样张组（多帧 batch）：1～3 个代表帧
         必须能证明：入口、对象/作用范围、核心状态变化、去向/返回
         建议闸：交互完整性、当前 HTML 与截图绑定、独立评审 fresh PASS
   ↓ ■停：交用户拍样张（方向/壳/信息密度/核心交互）；确认后才准铺开
         用户明说「直接铺开」→ 可跳过人工样张停点，不建议跳过机器/独立评审
Stage 3b 批量铺开其余帧（按澄清编译/装配，禁二次创作）
         闸：容器/标注合规 + 规范自核 +（如有）真实-vs-本地对比
   ↓
Stage 3.5 交卷前自评（运动员自检自修，非自评判过）
         闸：自检声明完整有证据；低级漏先改掉再交裁判
   ↓
Stage 4  独立评审（运动员/裁判分离）
   ↓ ■停：交用户终审
Stage 5  收尾沉淀 → 按需回写 PRD（只回需求事实，不写生产账）
```

**判定快捷**：纯复刻已有模块（无新交互/无新数据）可在结构稿判定「跳过/轻量」进 Stage 2；新增模块 / 没遇过的新形态 / 大改造 → 必走全套。

**产出契约**：每轮只推进**一个 Stage**，在停止点 end-turn；写明现处第几 Stage、下一步是产物还是等用户。

---

## 最高纪律：人工审阅闸

> **产物 ≠ 过闸。过闸 = 用户真的审过。**

把结构/澄清/样张/终稿一口气全产出、自己把「用户已确认」填上 = **自导自演，严重违规**。

1. **一轮只产一个 Stage 的产物，然后必须停。**
2. 「用户已确认结构」「澄清审阅通过」是人工专属字段，AI 禁止自填——只能在用户**后续轮次明确批准**后，引用用户原话回填。
3. Stage 间「是否进入下一步」是人工拍板，不是机制自过。
4. 用户已接受 ≠ 总豁免：改文件后仍须按当前产物重核证据。

### 澄清与批次

澄清应含页面跳转流（入口→动作→目标→去向/返回）；纯单页可写 N/A + 理由。多 Batch 拆分时维护覆盖矩阵：每批声明覆盖哪些规格节，关闭需求时不得有未覆盖或过期项。
