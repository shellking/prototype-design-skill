## 全程不变的边界

- **真实源头**：已批准 PRD / 澄清 / 真实页 recon / 组件真相 才是源。未经核实的「理解 demo」不得当母版。
- **写第一行高保真 HTML 前必读**：本仓库容器设计系统全文；你们团队的产品壳/组件约定（放在私有库）；有前端源码时的组件真相卡。正文点名「已读」。
- **三层结构（固定）**：`.proto-frame ⊃ .proto-layout(row) ⊃ [.proto-stage ⊃ 壳 ⊃ 产品内容] + .note-panel`。产品层只放真实产品文案/控件；说明在右栏；每态独立成帧。局部改动用中性 wrapper 的红虚线 + 连续编号，不挂真实组件类名；净新增整页/整窗不圈虚线。
- **真实页身份**：每帧声明既有页局部改 / 净新增 / 样张。既有宿主页沿真实母版局部插入；真实壳 ≠ 真实内容已对齐。
- **样式与文案**：主按钮在左、取消在右；单区一个主按钮。新增交互先对照真实同类组件，走查最大/最小/空态；不确定时不要画「字面最简形」。
- **可见验证**：声称与真实对齐时，宽高/字号/overflow/截图差异均需证据。口头「差不多」无效。

## 阶段与人工审阅

```
Stage 0 recon → Stage 1 结构 → 【用户审结构】→ Stage 2 澄清 → 【用户审澄清】
→ Stage 3a 样张 → 【用户拍样张】→ Stage 3b 铺开 → Stage 3.5 自检 → Stage 4 独立评审 → 【用户终审】
```

- 每轮只推进当前获准阶段。
- 「用户已确认结构/澄清」等字段**只能引用真实后续用户输入**，AI 不得代填。
- 补充反馈 ≠ 放行。用户已有明确授权则按授权执行，不重复索要。
- 多帧 batch 的样张选 1～3 个代表帧，覆盖：入口、对象/作用范围、状态变化、去向/返回。用户要求「直接铺开」只豁免人工样张停点，机器/独立评审仍建议执行。

## 交付证据

结构通过不证明视觉正确。只有当前产物的检查证据 + 独立评审 +（如有）交付闸均通过，才可交用户终审。「用户接受」是状态，不是跳过检查的豁免。

## 每轮输出

列：本轮复用件、需规避问题、自验结果、截图对比（若声称对齐）、当前阶段、未决问题、默认决策、下一步。有降级就标明缺哪份证据。详见 [07-closeout](references/07-closeout.md)。
